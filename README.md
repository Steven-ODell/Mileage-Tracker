# Mileage Log

An Android app for keeping a mileage log good enough for the IRS, built for a
field job with many short drives between stops. You tap **Start day** when the
workday begins, **Mark stop** each time you park, and **End day** at the last
stop. Each leg is saved with its miles, start and end times, street addresses
and a purpose. The drive home is never recorded.

Everything is stored on the phone. There are no accounts, no server and no
cloud sync. The app is sideloaded as an APK and is not on the Play Store.

## Features

- **Background tracking** that survives a whole workday with the screen off.
  It runs as an Android foreground service, and that service's notification
  carries the Mark stop and End day buttons (an Android 16 Live Update where
  the phone supports it).
- **Purpose picker** after every stop: Inspection, Final walk, Canvassing,
  Adjuster meeting, Office, Supply run or Personal, plus an optional note. Or
  skip the buttons and type the reason; the typed text becomes the purpose.
  Personal legs don't count toward business miles.
- **Trip list** grouped by day, with daily and year-to-date business miles.
- **Edit, delete and manual entry** for drives you forgot to track.
- **Trim end**: if you forgot End day and the drive home got recorded, drag a
  slider back to where you really stopped. The cut points are kept, so you can
  undo it.
- **Route map** for each leg and each day (MapLibre GL with OpenFreeMap tiles,
  no API key needed).
- **CSV export and import** through the Android share sheet, plus a weekly
  reminder to export. Importing the same file twice doesn't create duplicates.
- **Crash safety**: every leg is written to SQLite when it starts. If the app
  is killed or the phone restarts mid-leg, the leg is kept and flagged with
  the time window where GPS was missing.
- **Warnings** when battery optimization could kill tracking, and a nudge
  after 30 minutes parked with a leg still recording.
- Light and dark mode, following the phone's setting.

## How miles are measured

Miles are the sum of distances between GPS fixes, with filtering so that GPS
drift doesn't add miles while the car is parked:

- Fixes with worse than 30 m accuracy are dropped.
- A fix only counts once it is at least 50 m from the last counted fix. Parked
  jitter stays below that.
- A jump faster than 60 m/s (about 134 mph) is treated as a glitch. If three
  fixes in a row agree with each other but not with the anchor, the anchor was
  the bad one and the track re-anchors on them.

The same filtered track draws the map line and drives the trim slider, so the
map shows exactly what was counted. The logic is in `src/geo.ts` and has no
dependencies, so it is tested with plain Node.

## CSV format

The export covers every leg since January 1 of the current year, with these
columns in this order:

```
date, leg, start_time, end_time, from_address, to_address, miles, purpose, note, from_lat, from_lng, to_lat, to_lng
```

Dates are `YYYY-MM-DD` and times are local 24-hour `HH:MM`. Import also
accepts `M/D/YYYY` dates and 12-hour times, because Google Sheets and Excel
rewrite them that way when a file is opened and saved again.

## Privacy

Trips, GPS points and settings stay in a SQLite database on the phone. Two
things do go over the network:

- **Map tiles** come from OpenFreeMap when you open a map, so their server can
  see which area you're viewing.
- **Street addresses** come from Android's built-in reverse geocoder. On most
  phones that is a Google service, which receives the coordinates of each stop.

## Building

You need Node, JDK 17 and the Android SDK. The build script loads the JDK
through [mise](https://mise.jdx.dev/) (see `.mise.toml`).

```bash
npm install                # also generates the inlined map page
./scripts/build-apk.sh     # -> build/mileage-log.apk
```

The result is a standalone release APK, signed with React Native's standard
debug keystore. That's fine for sideloading. Keep signing with the same key:
Android refuses to install an update signed with a different key, and
uninstalling to get around that deletes the database.

`android/` is generated by `expo prebuild` and isn't checked in. Native
settings live in `app.json`.

## Tests

```bash
npm test          # distance math, drift filter, gap detection, CSV round trips
npx tsc --noEmit  # typecheck
```

`scripts/emu-drive.sh` drives the app on an Android emulator: it installs the
APK, taps buttons and replays fake GPS drives, so tracking can be checked
without getting in a car. Run it with no arguments for usage.

## Project layout

| Path | What's there |
|---|---|
| `App.tsx` | Home screen and a small navigation stack |
| `src/tracking.ts` | Background location task, Start day / Mark stop / End day |
| `src/geo.ts` | Distance math, drift filter, gap detection (no imports) |
| `src/db.ts` | SQLite schema, migrations and queries |
| `src/csv.ts` | CSV writing, parsing and duplicate detection (no imports) |
| `src/notify.ts` | Tracking notification buttons and the parked nudge |
| `modules/tracking-notification` | Local native module that puts the buttons on the tracking notification |
| `src/backup.ts` | Export, import and the weekly reminder |
| `map/map.html` | MapLibre map page, inlined into the app at build time |

Built with Expo SDK 57, React Native 0.86 and TypeScript.

## Not tax advice

The log records what the IRS asks for (date, destination, business purpose,
miles), but check with a tax professional about how you use it.
